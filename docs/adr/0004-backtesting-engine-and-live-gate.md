# ADR 0004: Backtesting Engine and Live Mode Transition Gate

## Status
Accepted

## Context
Перед отправкой реальных сигналов пользователям или запуском автоматических действий необходимо:
1. Иметь воспроизводимый инструмент исторического бэктестинга стратегий без искажений и с честным учетом затрат (комиссии, проскальзывание).
2. Иметь строгий программный шлюз (Live Mode Gate), блокирующий несанкционированный или неподготовленный переход из режима симуляции (`DRY_RUN=true`) в боевой режим (`DRY_RUN=false`).

## Decision

### 1. Backtesting Engine (`src/collectibles/analyzer/backtester.py`)
- Исторические котировки сортируются строго по возрастанию `event_time`.
- Для каждой пары источников и предмета состояние обновляется в хронологическом порядке, что исключает Look-Ahead Bias.
- Моделирование сделок учитывает:
  - Комиссию покупки и продажи (`FeeCalculator`).
  - Проскальзывание цены исполнения (`slippage_percent`).
- Вычисляемые метрики:
  - `total_trades`: общее число сработавших сигналов.
  - `precision`: доля сделок, принесших чистую прибыль $> 0$.
  - `false_discovery_rate` (FDR): доля убыточных или нулевых сделок ($1 - \text{precision}$).
  - `total_net_profit_usd`: суммарная прибыль в базовой валюте (Decimal).
  - `max_drawdown_usd`: максимальное снижение эквити портфеля от пика.

### 2. Live Mode Gate Validator (`src/collectibles/core/live_gate.py`)
- Класс `LiveGateValidator`, проверяющий 5 обязательных условий §11:
  1. `user_confirmation`: явное подтверждение от оператора.
  2. `git_commit_sha`: фиксация неизменяемого хэша коммита кода.
  3. `circuit_breakers_closed`: все предохранители в статусе `CLOSED`.
  4. `dlq_empty`: отсутствие застрявших сообщений в Dead-Letter Queue.
  5. `kill_switch_verified`: подтвержденная готовность аварийного отключения `STOP_ALL_OUTBOUND=1`.
- При нарушении хотя бы одного условия выбрасывается исключение `LiveGateBlockedError`, и переход в боевой режим блокируется.

## Consequences
- Любой алгоритм детекции валидируется математически до боевого развертывания.
- Случайный или ошибочный переход в LIVE без аудиторского следа программно невозможен.
